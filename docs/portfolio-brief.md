# Brief de Proyecto — TrejoDev Portfolio

## 1. Resumen del proyecto

Crear un portfolio profesional desde cero para **TrejoDev**, enfocado en conseguir empleo como **Frontend Developer** en general, evitando posicionarlo explícitamente como “Senior Frontend Developer”.

El portfolio debe cubrir desde el diseño visual hasta el desarrollo y despliegue en **Firebase**, reemplazando por completo el portfolio anterior que ya existe en un proyecto Firebase del usuario.

El proyecto se construirá en un **repositorio nuevo**, usando **React + Next.js**, con una estructura multipágina, soporte bilingüe y una identidad visual **Creative Pro**: creativa pero profesional, memorable, recruiter-friendly, con tipografía fuerte, contraste editorial, detalles visuales controlados y jerarquía clara.

## 6. Stack técnico

Stack elegido:

```txt
React + Next.js + TypeScript + Tailwind CSS + Firebase Hosting
```

### Recomendaciones técnicas

- Usar **Next.js App Router**.
- Usar **TypeScript** en todo el proyecto.
- Usar **Tailwind CSS** para estilos.
- Usar arquitectura por features/secciones.
- Preparar soporte de i18n desde el inicio.
- Optimizar para SEO, performance, accesibilidad y responsive design.
- Evitar dependencias innecesarias.

### Animaciones

Usar animaciones **muy sutiles**:

- Hover states.
- Transiciones suaves.
- Fade-in ligero por sección.
- Microinteracciones discretas.

No usar animaciones pesadas, efectos excesivos o elementos que perjudiquen el rendimiento.

## 7. Deploy

El portfolio debe desplegarse en **Firebase**, reemplazando completamente el portfolio anterior.

### Reglas de deploy

- Crear el proyecto en un repositorio nuevo.
- Conectar o desplegar al proyecto Firebase existente donde vive el portfolio anterior.
- No crear un proyecto Firebase nuevo salvo que el usuario lo pida después.
- Al hacer deploy, el portfolio anterior debe ser sustituido por el nuevo.
- Mantener una configuración clara para futuros deploys.

### Consideración técnica

Firebase ofrece soporte para desplegar apps Next.js mediante su integración de frameworks y también Firebase App Hosting para apps modernas con frameworks. Elegir la vía más adecuada durante la implementación según las necesidades reales del proyecto.


El diseño debe verse:

- Profesional.
- Limpio.
- Elegante.
- Recruiter-friendly.
- Confiable.
- Técnico sin parecer recargado.
- Memorable por su personalidad visual controlada, no por ruido o efectos exagerados.

### Dirección visual

El portfolio debe priorizar:

- Mucho espacio respirable con base clara, blanco cálido y contraste negro.
- Tipografía fuerte con jerarquía editorial clara.
- Layouts amplios, escaneables y con asimetría sutil.
- Contraste alto y lectura rápida.
- Componentes sobrios con bordes sutiles y detalles memorables.
- Secciones fáciles de escanear para recruiters.
- Señales técnicas claras sin estética cyberpunk, neon, dashboard-heavy o infantil.
- Detalles visuales con intención: paneles oscuros, acentos cálidos, barras de color, marquee tecnológico y microinteracciones discretas.

### Paleta sugerida

- Fondo principal: blanco cálido / off-white.
- Superficies: blanco, negro suave o crema claro.
- Texto principal: negro casi puro o blanco cálido en secciones oscuras.
- Texto secundario: gris neutro.
- Acento principal: naranja cálido contenido, acompañado por acentos secundarios verdes/azules solo como detalle.
- Bordes: grises sutiles de bajo ruido visual.

Ejemplo conceptual:

```txt
Light Background: #fbfaf7 / #ffffff
Dark Background: #0a0a0a
Light Surface: #ffffff
Dark Surface: #18181b
Primary Text Light: #0a0a0a
Primary Text Dark: #ffffff
Secondary Text: #525252 / #a3a3a3
Border: rgba(10, 10, 10, 0.10) / rgba(250, 250, 250, 0.12)
Accent Primary: #ff6b35, used sparingly
Accent Secondary: #86efac / #93c5fd, used only as small visual signals
```

### Foto / avatar

No usar foto personal.
No usar avatar por ahora.
La identidad debe apoyarse en:

- Marca textual TrejoDev.
- Tipografía.
- Layout.
- Cards.
- Detalles visuales.
